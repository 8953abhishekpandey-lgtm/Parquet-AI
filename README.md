# ⚡ Parquet AI — Enterprise Secure Analytics Platform

A **full-stack secure enterprise AI analytics platform** for querying dynamic parquet files using natural language. Built with a **Retrieval-Augmented Generation (RAG)** architecture that ensures raw data **never leaves your local system**.

---

## 🏗️ Architecture Overview

```
PARQUET FILES (LOCAL)
       ↓
SPARK + DUCKDB (LOCAL)
       ↓
SCHEMA EXTRACTION (LOCAL)
       ↓
LOCAL EMBEDDINGS (sentence-transformers / all-MiniLM-L6-v2)
       ↓
QDRANT VECTOR DB (LOCAL — embedded mode)
       ↓
LOCAL SEMANTIC RETRIEVAL
       ↓
MINIMAL CONTEXT ONLY ──→ ANTHROPIC CLAUDE API (reasoning + SQL generation)
       ↓
LOCAL DUCKDB EXECUTION
       ↓
CLAUDE ANSWER GENERATION
       ↓
FINAL INTELLIGENT RESPONSE
```

### 🔒 Security Model

| Component | Location | What happens |
|-----------|----------|--------------|
| Parquet files | **LOCAL** | Stored in `uploads/`, never uploaded externally |
| Embeddings | **LOCAL** | Generated by `sentence-transformers` on your machine |
| Vector DB | **LOCAL** | Qdrant runs in embedded mode (no network calls) |
| Semantic retrieval | **LOCAL** | Vector similarity search runs entirely locally |
| SQL execution | **LOCAL** | DuckDB queries parquet files directly on disk |
| Claude API | **EXTERNAL** | Receives ONLY: column names, types, ≤5 sample values, semantic snippets |

**What is NEVER sent to Anthropic:**
- ❌ Full parquet files
- ❌ Entire datasets or tables
- ❌ All rows of data
- ❌ Raw embeddings or vectors
- ❌ Sensitive bulk data

## 🚀 Setup Instructions (PowerShell — Windows)

### Prerequisites
- Python 3.10+ with pip
- Node.js 18+ with npm
- (Optional) Docker Desktop for containerized Qdrant

### Step 1: Clone and navigate
```powershell
cd C:\Users\katiy\Desktop\AI\Parquet-AI-Development
```

### Step 2: Create `.env` file
```powershell
Copy-Item .env.example .env
```

Edit `.env` and add your **Anthropic API key**:
```env
ANTHROPIC_API_KEY=sk-ant-your-actual-key-here
```

> **Note:** If you don't set `ANTHROPIC_API_KEY`, the app will still work using rule-based SQL generation (without Claude intelligence).

### Step 3: Install Python dependencies
```powershell
# Create virtual environment
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# Install all dependencies
pip install -r requirements.txt
```

### Step 4: Install frontend dependencies
```powershell
cd frontend
npm install
cd ..
```

### Step 5: Start the backend
```powershell
# From the project root directory
.\.venv\Scripts\Activate.ps1
uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000
```

### Step 6: Start the frontend (new terminal)
```powershell
cd frontend
npm run dev
```

### Step 7: Open in browser
Navigate to **http://localhost:5173**

## 🔄 Demo Flow

1. **Upload** — Drag & drop `.parquet` files into the upload zone
2. **Schema Detection** — Columns, types, stats are extracted dynamically
3. **Embedding Generation** — Local `all-MiniLM-L6-v2` creates embeddings
4. **Vector Storage** — Qdrant stores semantic metadata locally
5. **Ask a Question** — Type natural language in the chat panel
6. **Semantic Retrieval** — Qdrant finds relevant columns via cosine similarity
7. **Claude Reasoning** — Minimal context sent to Claude for SQL generation
8. **SQL Execution** — DuckDB runs the query locally on your parquet files
9. **Intelligent Answer** — Claude generates a natural language response

## 🧠 RAG Architecture Explained

**Retrieval-Augmented Generation (RAG)** combines local retrieval with LLM reasoning:

1. **Index Phase**: When you upload a parquet file, the system:
   - Extracts schema (columns, types, stats) using DuckDB + Spark
   - Generates semantic text for each column (name, type, sample values)
   - Creates embeddings using `all-MiniLM-L6-v2` (runs locally)
   - Stores vectors in Qdrant (runs locally in embedded mode)

2. **Query Phase**: When you ask a question:
   - Your question is embedded locally
   - Qdrant finds the most semantically similar columns
   - Only column names, types, and ≤5 sample values are sent to Claude
   - Claude generates a DuckDB SQL query
   - DuckDB executes the SQL locally on your parquet files
   - Claude generates a natural language answer from the results

## ⚙️ Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `ANTHROPIC_API_KEY` | (none) | Your Anthropic API key |
| `ANTHROPIC_MODEL` | `claude-sonnet-4-20250514` | Claude model to use |
| `ANTHROPIC_MAX_TOKENS` | `1024` | Max tokens for Claude response |
| `ENABLE_CLAUDE_REASONING` | `true` | Toggle Claude on/off |
| `QDRANT_MODE` | `embedded` | `embedded` or `server` |
| `QDRANT_URL` | `http://localhost:6333` | Qdrant server URL |
| `QDRANT_COLLECTION` | `parquet_semantic_metadata` | Collection name |
| `EMBEDDING_MODEL` | `all-MiniLM-L6-v2` | Sentence transformer model |
| `ENABLE_SPARK_SCHEMA` | `true` | Enable Spark schema reader |
| `SAMPLE_ROWS` | `20` | Sample rows to extract |
| `QUERY_ROW_LIMIT` | `100` | Max rows per query |

## 🎯 Key Features

- **Dynamic Schema Handling** — No hardcoded schemas; adapts to any parquet structure
- **Semantic Search** — Natural language maps to columns via vector similarity
- **Secure RAG** — Raw data never leaves your machine
- **Claude AI Intelligence** — Generates precise SQL and natural language answers
- **Automatic Fallback** — If Claude is unavailable, uses rule-based SQL generation
- **Multi-Table Queries** — Query across multiple uploaded parquet files
- **Security Audit Panel** — Frontend shows exactly what data was sent externally
- **Outlier Detection** — Z-score based anomaly detection
- **Trend Analysis** — Time-series grouping (daily, weekly, monthly, yearly)
